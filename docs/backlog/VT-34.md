# VT-34: A lane can stop mid-ticket silently — record the stop state, name it on the ticket, red it when it goes stale
- status: In Review
- labels: gate, doctrine, adapter, hooks
- estimate: 0.5d
- type: Task

**30-second summary:** the 2026-09-03 benchmark arm ended with 11 uncommitted files, a red
unit suite, no closing entry in RUNLOG.md and the ticket still "In Progress" — two weeks later
the operator had to reconstruct the stop from `git status`. Now: `stop_state.sh` writes
`{paths.evidence}/<KEY>/dev/STOP-STATE.md` (branch, HEAD, uncommitted files, last gate line)
whenever a session ends with a ticket in flight; Claude Code runs it from a `SessionEnd` hook
the adapter installs; the dev workflow gains a "Stopping mid-ticket" rule (WIP commit or dirty
tree, but ALWAYS the stop state; `Blocked` + reason when it is not a hand-off); `graph_check`
reds a STOP-STATE.md older than 7 days on a ticket that is neither Done nor Blocked.

## Why
docs/BENCHMARK.md "How the two runs went": the stop itself was legitimate (budget), the
silence around it was not. A framework whose pitch is evidence per claim must leave evidence
for the one event every long run has — the stop. Spec: core/workflows/dev.md (T5/T6 hand-off
rules), adapters/claude-code.mjs (hook install path), core/scripts/graph_check.py (coherence
rules). no UI.

## Acceptance criteria
- Given a `feat|fix/<KEY>-…` branch with a dirty tree or commits ahead of the base / When `stop_state.sh` runs / Then `STOP-STATE.md` exists with `recorded:`, `branch:`, `head:`, `base:`, `uncommitted:` and the `git status --short` block, the tasksheet carries exactly one `- stop-state:` line however many times it runs, and the exit code is 0.
- Given a clean tree on the protected branch, or no derivable ticket key / When it runs / Then nothing is written and the exit code is 0.
- Given a fresh `vteam init --tools claude-code` / When `.claude/settings.json` is read / Then it carries a `SessionEnd` entry calling `.claude/hooks/vteam-session-end.sh`, both hooks are in the manifest, and a user's pre-existing hooks survive the merge.
- Given a ticket neither Done nor Blocked with a `STOP-STATE.md` recorded more than 7 days ago / When `graph_check.py` runs / Then it is RED naming the ticket; Blocked, Done, or a fresh stop state pass.
- Given tests/e2e.mjs / When it runs / Then the README's selftest count (35) and check count (207) still verify.

## Out of scope
Hooks for other agent tools (they get the doctrine line only); auto-transitioning the ticket to Blocked (a status change is a human-readable claim the lane makes on purpose, not a side effect of closing a window); a `wip(KEY):` commit made by the hook (never commit for the user).
