# VT-18: let the graph and the ledger reference the decision queue

- status: In Review
- assignee: Connor Pham
- estimate: 0.25d
- labels: gates, graph, decisions, from-field-trial

## Why

Two states that happen constantly had no way to be written down, so they were written in prose —
and prose is invisible to a gate.

**A ticket blocked by a decision, not by another ticket.** TB-9 waits on "is high contrast a
supported target?" (`Q8`). Writing `blocked-by: Q8` made `graph_check` red it as a dangling edge, so
the dependency went into a blockquote. A gate reading that backlog sees a startable ticket.

**A ticket closed by a decision instead of a verdict.** TB-7 was closed won't-fix: the owner kept a
documented UX rule and declined the change. `graph_check` demanded `evd/TB-7/REPORT.md` — *"only QA
closes, and QA's act IS the verdict"* — which is right for work that was built and wrong for work
that was declined. There is nothing for QA to verify. The only honest alternatives were to fabricate
a QA report or to leave the ticket open forever.

**A ledger row citing a decision that does not exist.** On 2026-09-10 a script writing a new `D13`
row raised on a percent sign, the row was never written, and both the commit message and the ledger
entry pointed at `D13` anyway. The ledger looked complete and cited nothing. It was caught by
re-reading a file, not by any check.

## Acceptance criteria (testable)

1. **Given** `blocked-by: Q8` where `Q8` is a row in `decisions.md`, **When** `graph_check` runs,
   **Then** it is accepted as a real edge — and while the row is not `DECIDED`, the run prints
   `⏸ <KEY> is blocked by decision Q8` and still **exits 0**: an unanswered question is a state, not
   a fault.
2. **Given** `blocked-by: GHOST-9`, matching neither a ticket nor a decision, **Then** it still reds.
3. **Given** a terminal ticket with no `REPORT.md` that cites a `✅ DECIDED` row, **When**
   `graph_check` runs, **Then** the closure is accepted.
4. **Given** the same ticket citing a `🔴 OPEN` row instead, **Then** it reds with *"a ticket cannot
   be closed by a question"*.
5. **Given** a terminal ticket with no `REPORT.md` and no decision cited at all, **Then** the
   original MAST 1.2 error still fires, now naming the decisions file as the alternative.
6. **Given** a ledger row citing `D13` when the queue holds no `D13`, **When** `log_check` runs,
   **Then** it reds. A row citing a decision that exists stays green.
7. Both selftests green, with the new cases added to `graph_check --selftest` rather than asserted
   by hand.

## Out of scope

- Any change to what `done_statuses` means. `Closed` stays a closure; what changed is what can serve
  as its evidence.
- Auto-releasing a blocked ticket when a decision is answered. The edge simply stops printing `⏸`;
  no status is rewritten, because moving someone else's ticket is not a gate's job.
