# VT-30: Gates that crashed, lied or went vacuously green in a real repo — the benchmark arm's E1/E4/E5/E7/E10/E14/E15/E16
- status: In Review
- labels: gate, field-finding, setup-tax
- estimate: 1d
- type: Bug

**30-second summary:** the vteam arm of the BMAD benchmark spent 4 h 29 min before its first feature
commit; its RUNLOG lists 16 environment findings, and eight of them are the framework's own gates
misbehaving in an ordinary Next.js repo: preflight RED because a local-only repo has no origin (E1);
verbatim_gate recognising zero rows of an `AC-A01`-coded spec and passing vacuously (E4); token_check
crashing with ENOENT on an App-Router layout (E5); app_check reporting a stranger's server as UP
(E7/E15); a gate piped to grep blocking forever in the background (E10); a commit announcing a ledger
row it never wrote (E14); a red-proof against a stale production build (E16). Each is fixed with a
test that was RED first, and the testbed dry-run showed its verbatim gate had been vacuous all trial.

## Why
Setup tax is the largest measured cost in docs/BENCHMARK.md and most of it was gates not doing their
job. Spec: ~/Documents/vteam-vs-bmad/arm-a-vteam/RUNLOG.md rows E1–E16 (owner's machine), summarised in
docs/BENCHMARK.md "How the two runs went". no UI.

## Acceptance criteria
- Given a repo with no origin remote / When preflight runs / Then it is GREEN with a ⚠️ line naming the local-merge rule, not RED (E1).
- Given `specs.sources` configured and a source whose rows are `| AC-A01 | …` / When verbatim_gate runs / Then those rows are truth rows; and given sources with zero coded rows / Then the gate is RED naming the expected row shape, never a vacuous pass (E4).
- Given `git.code_paths` without `src/` / When token_check runs / Then it scans the configured directories and never throws on a missing one (E5).
- Given a listener on app.url's port whose cwd is outside this repo and its worktrees / When app_check runs / Then it prints `APP: FOREIGN …` and exits 1; a listener from this repo stays UP (E7/E15).
- Given gate.sh / When it runs / Then the full transcript is also in a file it names on its last line (E10).
- Given a ticket In Review or Done with no ledger row naming it (and no `closed-by:`) / When graph_check runs / Then it is a coherence violation (E14).
- Given /verify principle 6 / When read / Then it says a red-proof against a built server needs a build on both sides of the revert (E16).

## Out of scope
E2 (init prefill + unique port) is VT-31; E13 (parallel lanes sharing one DB/port) is its own ticket; E8/E9/E12 are Next.js or host behaviour; E11 was external interference. The testbed's now-visible vacuous verbatim gate is testbed work (its requirement docs carry no coded rows).
