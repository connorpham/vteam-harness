# VT-19: `type:` routing token — D13 option (A), measured

- status: In Review
- assignee: Connor Pham
- estimate: 0.25d
- labels: doctrine, competencies, context, routing, from-field-trial

## Why

D13 asked how `applies:` should stop over-routing, with numbers from VT-16: the field trial's worst
DEV ticket opened 15 competency files ≈ 17,270 tokens, and 5 of 9 dev ticket/lane pairs loaded at
least one competency pulled in by a word appearing only in the ticket's prose. The owner chose
**option (A)** on 2026-09-10: add a `type:` token first, because it is *additive* — it breaks no
existing `applies:` line — and then re-measure before going further.

`type:` matches the ticket's own `type:` field. Two Bug tickets were loading `dev-debugging` because
the word "bug" appeared in a sentence, not because they were bugs. The field is the structural truth
the ticket already states, and prose cannot trigger it.

## What changed

- Grammar: `always | label: | path: | profile: | term: | type:<IssueType>`, in
  `competency_check.py` and `route_check.py` (which now treats `type` as a structural field).
- `dev-debugging`: `term:bug` → `type:Bug`. `label:bug` stays, for repos that route by label.
- `dev-observability`: dropped `term:logging` and `term:incident` — the first matches any ticket that
  mentions a log in passing, the second duplicates `label:incident`.

## Measured, on the field trial's nine tickets

| | files | tokens |
|---|---|---|
| before | 84 | 88,191 |
| after | **81** | **84,863** |
| delta | −3 | **−3.8%** |

Excluding TB-9, which grew because it was **rewritten longer today** for unrelated reasons (QA
corrections), the eight remaining tickets go 76 → 72 files and **−6.0%**.

On the two Bug tickets the file count is unchanged and the *reason* is now right:
`dev-debugging ← type:Bug in type` instead of `← term:bug in body`. That is the point of option (A)
— it makes routing legible before it makes it smaller.

## What it does not fix, with the evidence

**5 of 9 dev pairs still carry a body-only match.** The clearest example is TB-9 itself: a ticket
about focus outlines pulls in `dev-async-work` because the word **"queue" appears once** in its
prose. `type:` cannot help there — the ticket's type is Bug and the false match is a `term:`. Closing
that needs D13 option (B) (require a `term:` to land in a structural field or appear twice) or (C)
(cap the routed set and rank by match strength), both of which change behaviour for every competency
and were deliberately left to a second decision.

## Acceptance criteria (testable)

1. `applies: type:Bug` passes `competency_check`; `applies: types:Bug` still fails with the token
   error naming all six kinds.
2. `route_check --ticket <a Bug ticket> --role dev` shows `dev-debugging ← type:Bug in type`, and
   the row is **not** flagged body-only.
3. A non-Bug ticket whose prose contains the word "bug" no longer loads `dev-debugging` on that
   basis.
4. The before/after file and token counts above are reproducible from `route_check --json`.
5. `competency_check --selftest` green; all 31 competencies still well-formed and indexed.

## Out of scope

- D13 options (B) and (C). This ticket exists to measure (A) alone so the next decision has a number
  rather than an argument.
- Rewriting other `term:` tokens. Only the two that `type:` replaces or that duplicate a label were
  touched.
