# VT-15: close the two doctrine holes the field trial measured, and let `gate e2e` reach e2e

- status: In Review
- assignee: Connor Pham
- estimate: 0.5d
- labels: doctrine, competencies, gates, a11y, from-field-trial

## Why

Two real tickets on the testbed project (TB-6, TB-8) turned on knowledge that was in
**none** of the 31 competencies, and one of them shipped an acceptance criterion that
could pass over a live defect. Both were found by running the lanes for real, not by
reading the doctrine. This ticket writes back what the field trial measured.

**Hole 1 — the second rendering mode was absent from the whole doctrine.** `grep -ril
'forced.colors\|high contrast' core/doctrine/` returned nothing across all 31 files.
Chrome paints no `box-shadow` under `forced-colors: active`, so an indicator built only
from `ring-*` changes **0 pixels** there while passing every default-mode check. That is
not a subtle regression, it is no indicator, and it is invisible to exactly the people
who turn the setting on. TB-6 spent a review round discovering it; TB-8 was its sequel;
a third instance (a search box and two dropdowns on the same screen) is still live on
the testbed and was found by walking the keyboard journey in that mode.

**Hole 2 — a criterion can be concrete, bounded, machine-checkable and still vacuous.**
TB-8's AC3 asked for a source-code search to come back empty. A build was made that
satisfied exactly that criterion and **rendered identically to the broken one**
(0 / 100 / 112 changed pixels before, 0 / 100 / 112 after). `qa-requirement-smells`'
three-line test passes that criterion. `ba-acceptance-criteria` had the right one-liner
("assert only what is observable from outside") but no failure mode, so it did not fire.

**Machinery — `gate e2e` had never run on the testbed.** The `integration` step ran
`{package_manager} run test:integration` with no guard, so on a repo without that script
the tail mode died one step before the e2e it exists to reach. The driver already had the
mechanism (`requires_cmd` + `skip_reason`); the manifest simply did not use it.

## Acceptance criteria (testable)

1. **Given** the doctrine, **When** `grep -ril 'forced.colors' core/doctrine/` runs,
   **Then** it names at least the verify-side competency, the build-side competency and a
   reference file — and the reference states the measured numbers, not a summary of a spec.
2. **Given** `qa-accessibility-verification` and `dev-frontend-craft`, **When** their word
   counts are measured, **Then** both are ≤ 1100 (`competency_check`'s ceiling) with the new
   rules present — i.e. the additions were paid for by moving lower-urgency material into
   `reference/`, not by dropping a rule.
3. **Given** `ba-acceptance-criteria` and `qa-requirement-smells`, **When** a reader applies
   them to TB-8's AC3, **Then** both now produce the finding: each carries the falsification
   question *"if this check passed and the behaviour were still broken, what would that look
   like?"* with the field example.
4. **Given** a repo with no `test:integration` script, **When** `gate e2e` runs, **Then** the
   step is a **declared skip** and the e2e step after it executes. Before/after step counts
   pasted.
5. `competency_check` green, `bash .vteam/scripts/gate.sh` green, and the same fix applied to
   the testbed's own profile with the before/after gate output as evidence.
