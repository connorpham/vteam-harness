# VT-37: the graph knew the order and printed it; the PM lane derived it again in prose
- status: In Review
- labels: graph, cost, orchestration
- estimate: 1d
- type: Task

**30-second summary:** `vteam graph` computed dependencies, cycles and a `ready` flag, and then
/pm P1 worked out the dispatch order itself — seven UNBLOCKED conditions across every open ticket,
every session, as LLM reasoning. Ordering a DAG is Kahn's algorithm. `vteam graph --plan` now
returns the waves, the scope-disjoint batches capped at `team.parallel`, the lane each item is
owed, what is in flight, what is blocked and why, the critical path by day-cost, and the upstream
evidence each agent should read first. /pm and /team consume it and adjudicate only what the plan
prints as not its call.

## Why
Measured on this repo: the ordering input was 35 open ticket files plus the plan, ledger and
decision queue — 170,772 bytes ≈ 42,693 tokens — and the order itself was then reasoned. The plan
is 9,720 bytes ≈ 2,430 tokens and is computed. Three further claims in the same critique were
measured and are FALSE for this repo, recorded in proof.md §1 so nobody re-opens them: reviewers
already run in parallel (dev.md T4b spawns them in one message), the gate's 14 bookkeeping steps
cost 1.3 s of a 90.8 s run (the test suite is 98.6 %), and the graph was never purely passive — it
already computed `ready`. Spec: `core/workflows/pm.md` P1 legs (a)–(g), `core/workflows/team.md`. no UI.

## Acceptance criteria
- Given a backlog with a blocked-by chain / When `graph --plan` runs / Then the chain is consecutive waves, a dependency already Done adds no level, and a ticket in a cycle or waiting on a decision is listed as blocked with the reason instead of appearing in a wave.
- Given `team.parallel: N` and declared `CODE-SCOPE`s / When the plan batches a wave / Then no batch exceeds N and no two items in one batch touch the same path; an undeclared scope takes its batch alone and is named in the warnings.
- Given a ticket In Review / When the plan runs / Then its lane is `/qa` and its scope is its own evidence directory, so a verification never consumes a code-writing slot.
- Given a pushed `feat|fix/<KEY>-*` branch / When the plan runs / Then the ticket is in flight, not dispatchable.
- Given a day-cost missing anywhere on the longest path / When the plan reports the critical path / Then it is marked INCOMPLETE and the missing tickets are named — the number is never guessed.
- Given /pm P1 / When read / Then it says to compute the order and adjudicate only the overrides, and the plan itself prints what it does not decide.

## Out of scope
Auto-dispatching agents from the plan without the lane (the plan advises, the lane dispatches, the gates are untouched); incremental gate caching (measured worthless here: 1.3 s of 90.8 s); pruning a DEV agent's context to its upstream contracts beyond the `read first` pointers this ticket adds.
