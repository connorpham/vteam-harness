# VT-23: the non-blocking residue from VT-22's three review rounds

- status: To Do
- assignee: Connor Pham
- estimate: 0.25d
- labels: gates, scripts, installer, from-review

## Why

Five items both reviewers explicitly declined to block VT-22 on, filed together so none of them
becomes folklore. Each carries the reviewer's own reasoning, because in two cases the reasoning is
the more valuable half.

## The items

1. **`closure_statuses()` has no selftest.** Fourteen config shapes were exercised by hand and none
   crashes or disarms, but the config-parsing path — which *was* the fix — is asserted nowhere. The
   selftest passes literal tuples into `sweep()` and skips it. R1: "coverage debt, not a defect",
   and it is the same house-rule miss VT-18's AC7 named ("new cases in the selftest rather than
   asserted by hand").
2. **A scalar `done_statuses` resolves to a status nothing can equal.** `done_statuses: 5` yields
   `{'5'}`, so the sweep quietly stops failing anything for that repo. The `or {"done"}` fallback
   catches an empty result but not a nonsense one. One line: if nothing resolved looks like a
   plausible status, fall back and say why, the way the unresolved-status path already does.
3. **`- closed-by: Q2 (won't fix, see the UX rule)` reds on the comma inside the parenthetical.**
   The item-splitter reads it as a second key. Narrow — the error now names the field, so a person
   drops the comma — but the fix is small: require each comma-item to *start* with a key and ignore
   the rest, instead of taking its first token.
4. **The manifest parser resolves a duplicate key silently, last-wins.** This bit twice inside one
   ticket: a duplicated `skip_reason` under `evd-ui` shipped in all six profiles, and the shipped
   line blamed a missing `evd/` directory for a missing Pillow — a gate telling a consumer the
   wrong reason it is not running. R2 argued specifically **against** making the parser error:
   it is shared with `vteam.config.yaml` in every consumer repo, so turning last-wins into a
   failure would red repos for a latent defect they have lived with. The right shape is a
   **warning from the driver** on a repeated key inside a step, with its own selftest.
5. **`owned` governs `vteam update`, not `vteam init`.** `init`'s `forceDir` clobbers regardless;
   reaching it needs a deliberate re-install (init refuses while `vteam.config.yaml` exists) and
   the file is recoverable from git. No code change asked for — one line of prose, because
   `update`'s current message ("remove it from `owned` to go back to receiving the framework's
   version") reads like a global property of the declaration.

6. **A `before_*`/`after_*`-only pack reaches the legacy exemption in one deletion.**
   `is_legacy_pack()` counts an image as "named" only through `NAME_PAT`, but `check_dev_dir`
   also accepts `before_`/`after_` and `design_vs_app.png`. So the one pack shape that
   legitimately has no `NN_`-named image — a bug-fix UI pack — is one `rm manifest.md` from the
   exemption. Found by attacking, not by reading, in round 4: it is the round-2 property
   surviving in a corner the general fix does not cover. Same one-line shape: widen the `named`
   test to the names `check_dev_dir` already accepts.

7. **Nothing guards `core/scripts/` → `.vteam/scripts/` the way `doctrine-source` guards
   `core/doctrine/`.** This repo runs its own gate from the mirror, and `doctor` compares
   mirror↔manifest — so a stale mirror and a stale recorded hash agree with each other and
   disagree with the source, and every signal reads GREEN. Found in review round 5 on a real
   instance: the fix to `gate.py` was committed in `core/` and not in `.vteam/`, so a clone of
   `HEAD` ran the previous driver while `doctor` said "manifest verified". Only a print string
   that time. It is VT-20 finding 3 one directory over — "the competency file arrived fresh, the
   INDEX arrived stale" — and the framework already decided it needed this check for doctrine and
   never generalised it. The step must be `requires:`-guarded on `core/scripts/` so consumer repos
   skip it by declaration, exactly as `doctrine-source` does, and its failure message must name
   `vteam update` as the remedy.

## Acceptance criteria (testable)

1. `evd_check --selftest` exercises `closure_statuses()` itself with at least a list, a
   comma-string, a scalar, an empty value and a `None` entry.
2. `done_statuses: 5` produces a declared fallback with a printed reason, not a silent `{'5'}`.
3. `- closed-by: Q2 (won't fix, see the rule)` closes the ticket; `- closed-by: Q2, GHOST-9` still
   reds on the unknown key.
4. A `gates.yaml` step with a repeated key produces a **warning** naming the step and the key —
   and the gate still runs. A selftest fixture proves it warns and does not fail.
5. Wherever `owned` is documented, it says it governs `update`.
6. A pack whose only images are `before_x.png` / `after_x.png`, with no `manifest.md`, is **not**
   legacy — deleting one file must not exempt it, the same way it does not for an `NN_`-named pack.
7. In the framework repo, every file under `core/scripts/` is byte-identical to its
   `.vteam/scripts/` counterpart, and a deliberate mismatch reds with `vteam update` named as the
   remedy. In a repo with no `core/scripts/`, the step is a declared skip.
