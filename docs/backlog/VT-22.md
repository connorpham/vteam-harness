# VT-22: act on both review cards — four blockers, and an instrument that was measuring prefixes

- status: In Review
- assignee: Connor Pham
- estimate: 0.5d
- labels: gates, scripts, installer, from-review

## Why

Two reviewers read the VT-15..VT-21 branch and both returned **REQUEST-CHANGES**, with 17
findings between them. Every blocker was reproduced before it was accepted. Several of them
turned rules that had just shipped into rules that did nothing.

## What was broken, and is now fixed

- **`evd_check --sweep` only enforced the literal status `done`** while this repo's own config
  declares `done_statuses: [Done, Closed, Resolved]`. A reviewer closed a pack claiming three
  cases and holding one simply by writing `Closed`. The gate VT-17 added to catch exactly that
  was passing it. Closure now comes from config; an unreadable status is a declared skip, never
  a silent pass.
- **`decision_settled()` was a substring test.** `UNDECIDED`, `not DECIDED yet` and
  `to be DECIDED` all read as settled — and it was the only gate on both the won't-fix closure
  and the blocked-by release. Now matches the declared `✅ DECIDED` marker.
- **The won't-fix closure accepted a decision key mentioned anywhere in the ticket.** "revisit in
  Q2" — or even "unrelated to Q2" — closed a ticket with no QA verdict, silencing MAST 1.2 on a
  token that collides with fiscal quarters. Now requires a structured `closed-by:` field, parsed
  like `blocked-by:`, with an unknown key red.
- **`evd-ui` was a hard gate step that reds a repo for its history.** A reviewer adopted vteam
  into a repo with one closed ticket and pre-standard screenshots and watched it go red. The
  legacy predicate covered only "images live in subfolders"; it now also covers the commoner
  shape — images at `dev/` with no `manifest.md` — and both are reported, not failed. It is also
  guarded on Pillow, which no Next.js or Go consumer has.
- **An advisory failure silently upgraded a WEAK green.** The four new steps were absent from
  `BOOKKEEPING`, so a repo with zero code verification started reading as an ordinary green just
  because `evd` had run; and the `— N ADVISORY FAILED` tail was built in one banner branch of
  three. Both fixed, and `advisory` must now be a real boolean — a quoted string is truthy and a
  typo would have taken a hard step out of the blocking path.
- **`owned` did not apply to a file that had not diverged yet**, so the guarantee lapsed the
  moment a fork happened to match the package — which is what happens right after a hand merge.
  The check moved above the refresh branch. It is also validated now: a bare string was being
  character-split into a bogus array **and written back over the user's hand-edit**.
- **`route_check` was matching prefixes.** `term:` compiled with a leading `\b` and no trailing
  one, so `term:lock` hit "lockfile", `term:form` hit "format", `term:api` hit "apiary" — silently
  inflating every body-only count D13's remaining options will be decided on. On the same nine
  field tickets the corrected count is **98 → 94 files**. `profile:` also only resolved for an
  absolute `--backlog`, which is the VT-20 undercount surviving in half the inputs, and `--strict`
  was documented as the opposite of what it does.
- **`log_check`'s citation rule was silenced by config and by a version number.**
  `decision_keys()` never received `paths.pm`, so a repo configuring anything else got an empty
  set and the rule disabled itself; and the foreign-key test matched `UTF-8`, `SHA-256`, `RFC-9457`.
- **`vteam doctor` told owned files the wrong story** — it promised a `.new` that never appears.

## What was added because a reviewer asked "what covers this?"

`route_check` had **no `--selftest` at all** — the one file that produced four different answers
for one measurement. It now has nine assertions, each guarding a mistake it actually shipped.
Cases were also added for both sweeps, the competency chain rule, the decision-citation rule, the
three uncovered `advisory` branches, and `owned` in the e2e suite (six checks, including the two
that were findings). Suite: **171/171**, with the README's stale counts corrected — the tripwire
that caught them is the suite's own.

## Acceptance criteria (testable)

1. A pack claiming more cases than it holds reds on `Done`, `Closed` **and** `Resolved`, and
   passes on `In Review`.
2. `UNDECIDED` does not settle a decision; a ticket mentioning `Q2` in prose does not close;
   `closed-by: Q2` against a DECIDED row does.
3. A repo with pre-standard UI evidence is **reported**, not failed, in both legacy shapes.
4. An advisory failure never upgrades a WEAK green, appears on every banner, and a non-boolean
   `advisory` reds.
5. `owned` holds for an unmodified file, parks nothing, and a malformed declaration is reported
   and left untouched on disk.
6. `term:lock` does not match "lockfile"; `term:lock` does match "locks".
7. Every checker in `core/scripts/` with a gate role has a passing `--selftest`; `npm test` green.

## Out of scope

- D13's options (B)/(C). The corrected numbers change the input to that decision, not the decision.
- The `owned` + `loads`-against-workflow coupling a reviewer flagged (a repo that pins a lane
  workflow reds when a competency ships a new `loads:` step). Documented, not solved.
