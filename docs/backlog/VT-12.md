# VT-12: parallel-run operations — login-expiry preflight, worker token accounting, robust derailment file listing, evidence-tree hygiene

- status: To Do
- assignee: Connor Pham
- estimate: 1.25d
- labels: gates, parallel, ops, qa, no UI

## Why

Findings from the first full `/team` day with two Orca workers + three QA runs
(2026-09-09, testbed). Each one cost the PM real time or produced a wrong
number; none is covered by VT-10 (gates in split worktrees) or VT-11 (monorepo
profile).

1. **Login expiry idled every agent at once.** Claude Code printed "login
   expires in 1 day" in each worker; when it expired mid-run, the Orca workers
   and both subagents stopped silently (`authentication_failed`) until the owner
   ran `/login`. Nothing in `preflight.sh` / `doctor` / `orca_team.sh` warned.
2. **No token accounting for Orca workers.** `worker_done` carries no usage;
   `usage --sync` scans `~/.claude/projects/<path>` for THIS repo's path, so
   sessions that ran in `~/orca/workspaces/<repo>/<worktree>` are invisible. The
   ledger's mandatory `tok ≈` had to be measured by hand from the worktree's
   JSONL (input + output + cache-create; cache reads excluded) or taken as the
   worker's estimate. Same root cause, second face: the PM's own `/team` session
   ran from a different directory (the framework checkout) — `usage --sync` in
   the project found **0 sessions** for a day with 7 done ledger rows and raised
   the "work that never ran?" flag. Worker self-estimates also proved unreliable
   (TB-4: 1350k estimated vs 2863k measured); and the harness's
   `subagent_tokens` for a QA subagent (560k) is a different basis from the
   transcript sum (2167k) — the doctrine must name ONE basis.
3. **`graph_check` derailment file listing is fragile.** It uses
   `git show --name-only --format= <sha>`: on a root/parentless commit that lists
   the WHOLE tree, and once on CI (pull_request merge ref, git 2.55) it listed
   files the commit does not touch — red at graph while the push job on the same
   SHA was green; not reproducible in three replays. Use
   `git diff-tree -r --no-commit-id --name-only <sha>` (empty for root commits,
   nothing for merges) and print the file COUNT in the red line so the next
   occurrence is diagnosable.
   **Reproduced on PR #63 (2026-09-09, docs-only PR):** the pull_request gate
   reded `VT-10: commit 8e13fd7e touches outside the declared CODE-SCOPE …
   .claude-plugin/marketplace.json, .claude/agents/ai-data-specialist.md, …` —
   the first files of the WHOLE TREE in path order, i.e. the commit was seen as
   parentless; the push-job gate on the same SHA was green. Local proof of the
   mechanism: in a `--depth 2` clone the shallow-boundary commit lists **367**
   files under `git show --name-only --format=` (1 file in the full clone), while
   `git diff-tree -r --no-commit-id --name-only` lists **0** — so the diff-tree
   form removes the false red whatever makes the commit look parentless. On CI
   the checkout logs `fetch-depth: 0` and HEAD = `refs/pull/63/merge`, so the
   parentless view there still has no explanation — the file count in the red
   line is what will settle it; until then a derailment check must skip a commit
   with no parent in the local graph rather than judge the whole tree.
   **Second data point (same day):** the red is DETERMINISTIC for this PR — two
   pushes, two pull_request reds on the same line, two push-job greens for the
   same SHAs. A local replay of `refs/pull/63/merge` (merge of 652a290 into
   8e13fd7, full clone) is GREEN with git 2.50.1 and lists 1 file for 8e13fd7
   with git 2.54.0 too; the CI runner has **git 2.55.0**. So the remaining
   suspect is the runner's checkout state or a behaviour change in git 2.55's
   `show --name-only --format=` — the fix (diff-tree + file count + skip
   parentless) is version-independent, and CI should print `git --version`
   next to the red line.
4. **Markdown tracker attachments are binaries in the repo.** `evd_check --attach`
   copies every image into `docs/backlog/attachments/<KEY>/`, which `init` does
   not git-ignore — `git add docs/` would commit 64 PNGs per ticket.
5. **`browser.mjs check` needs the `playwright` package** while Next projects
   install only `@playwright/test`; the QA lane had to create a `node_modules/
   playwright` symlink by hand.
6. **A journey re-run overwrites its captures in place** (no versioning), so a
   re-shoot after a fix silently destroys the "before".
7. **The vteam repo's own `.githooks/pre-push` is stale** (36 lines, does not run
   `review_check.py`) — the review fence is not armed on the framework repo
   itself; and the gate has no shell-lint step (a stray apostrophe broke a helper
   while every gate stayed green).
8. **Hostile fixture data leaks across lanes.** A reviewer's team named
   `<img src=x onerror=alert(1)>"; DROP TABLE x;--` sorted first and became the
   default team of another ticket's modal; probe rows piled up on the shared DB
   (~30 by the end) and only the PM could soft-delete them. Doctrine should
   require probe fixtures to be created under a recognisable prefix and removed
   (or soft-deleted) by the lane that made them before `worker_done`.
9. **`schedule_check` reads the wrong date from a decision row.** Line ~94 takes
   the FIRST cell that contains an ISO date, so a note such as "Owner 2026-09-09:
   leave it for now" in the Why/Blocker column shadows the real Due column — the
   testbed's A1 (due 2026-09-30, deferred by the owner) was reported as
   "🔥 due 2026-09-09 (0 days left)" and pushed the desk report into the burning
   list for nothing. Read the Due column by header position (or the LAST
   date-bearing cell), and add a selftest row whose note carries an earlier date.

## Acceptance criteria (testable)

1. **Given** the `claude` CLI reports a login expiring within 24 h, **When**
   `preflight.sh` (and `orca_team.sh status`) runs, **Then** a ⚠️ line names it
   and the hours left; **and Given** a worker dies with `authentication_failed`,
   **Then** `orca_team.sh wait` prints a one-line diagnosis instead of silence.
2. **Given** Orca workers ran in `~/orca/workspaces/<repo>/*`, **When**
   `usage --sync` runs in the repo, **Then** those sessions are included (matched
   by the git remote / repo identity, not the path) and the desk report's
   `tok ≈` can be filled from them; the ledger doctrine says which components
   count (input + output + cache-create).
3. **Given** a root commit attributed to a ticket, **When** `graph_check` runs,
   **Then** it does NOT list the whole tree (diff-tree, no `--root`); a red line
   carries the total file count; selftest mutation added.
4. `init` git-ignores `docs/backlog/attachments/**` for the markdown tracker
   (and `update` adds the rule when absent, loudly).
5. `browser.mjs check` explains the `playwright` vs `@playwright/test` gap and
   the exact install command; or `init` for web profiles adds `playwright` as a
   dev dependency step in its "Next" block.
6. Journey re-runs write to a timestamped or `_v<n>` folder, or refuse to
   overwrite without `--force`; `evd_ui_check` still finds the newest.
7. This repo's `.githooks/pre-push` equals the current template (review fence
   armed here), and `gate.sh` gains a `shellcheck`-or-`bash -n` step for
   `core/scripts/*.sh` with a declared skip when shellcheck is absent.
8. Doctrine (review-standard + qa) requires probe fixtures to carry a
   recognisable prefix and to be removed/soft-deleted by their lane before
   `worker_done`, and forbids hostile strings in fields that other lanes sort
   or default on unless soft-deleted in the same session.
9. **Given** a 🔴 OPEN decision row whose note column mentions an earlier date
   than its Due column, **When** `schedule_check` runs, **Then** the Due column's
   date is the one reported; selftest mutation added.
10. `gate.sh` GREEN, `doctor` green, `tests/e2e.mjs` green, README counts updated
   by the guard's numbers.
