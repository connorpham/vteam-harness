# VT-14: progressive disclosure for competencies — cut what the lane spends on the rulebook

- status: In Progress
- assignee: Connor Pham
- estimate: 0.5d
- labels: doctrine, competencies, context, performance, no UI
- blocked-by: VT-13

## Why

Reported from use, not from a gate: on a full task the agent forgets and
degrades. Measured, the complaint is real — the doctrine a lane accumulates by
the end of a task, before it reads a line of the ticket, spec or code:

| | `/dev` | `/qa` |
|---|---|---|
| skill catalogue (40 skills, every session) | 3,498 | 3,498 |
| lane `SKILL.md` | 6,617 | 6,844 |
| role doc + INDEX | 2,342 | 2,214 |
| `always` competencies | 5,260 | 8,595 |
| **floor** | **≈17,700 tok** | **≈21,150 tok** |

VT-13 made this worse in one way nobody measured at the time: the skill catalogue
went from ~2,448 to 3,498 tokens (28 → 40 skills), and that is paid in **every**
session regardless of lane.

The framework already had the mechanism — `competencies/qa/reference/`, loaded on
demand — and the twelve new files were not using it.

## Scope

1. Move `Rationalizations`, `Red flags` and `Example` out of the 16 `always`
   competencies into `competencies/<role>/reference/<name>.md`, one reference file
   per competency so loading one does not pull the others, each with a pointer from
   the competency's `Sources`. Those three sections are the ones
   `competency_check` does **not** require — which is what makes them movable.
2. Fix one `always` declaration that contradicts its own description:
   `qa-user-mindset` says "Use when designing or running **any UI verification**"
   — a condition, not always — so route it on
   `label:ui, label:frontend, label:mobile, label:design, path:app/,
   path:components/, path:src/components/, term:screen, term:page, term:form,
   term:button, term:modal, term:dialog, term:ux`.

## Out of scope, with reasons

- **The lane files themselves** (`qa/SKILL.md` 6,844 tok = 34% of the floor) — the
  largest single item and the largest available win, but the lane is the core
  procedure and the change is the riskiest. Separate ticket.
- **Trimming the 40-skill catalogue** (3,498 tok, every session) — descriptions are
  the routing mechanism; cutting them wrong makes skills undiscoverable.
- **`qa-heuristics`** — its trigger is "the spec is silent", which is discovered
  mid-work and cannot be matched from a ticket's labels, paths or text. Left `always`.
- **`qa-hostile-inputs`** — applies to every verification that has an input. Left `always`.

## Acceptance criteria

1. **Given** the 16 `always` competencies, **When** the three sections are moved,
   **Then** `competency_check` still exits 0 with 31 well-formed and indexed, and
   every file still carries all six required sections. *(evd/VT-14/competency-after.txt)*
2. **Given** the move, **Then** 2,459 words (~3,320 tokens) have left the default
   load path, and each competency's `Sources` points at its reference file.
   *(evd/VT-14/moved.txt)*
3. **Given** `qa-user-mindset` is routed, **When** the `/qa` floor is recomputed,
   **Then** it falls from 21,169 to 18,869 tokens (−2,300, −10.9%) on a **non-UI**
   verification, and is unchanged on a UI ticket because the tokens match.
   *(evd/VT-14/floor-before-after.txt)*
4. **Given** the whole change, **When** `bash .vteam/scripts/gate.sh` runs,
   **Then** GATE: GREEN, 164/164. *(evd/VT-14/gate-after.txt)*

## Definition of done

Criteria 1–4 verified by a fresh `/qa` run producing `evd/VT-14/REPORT.md` with a
PASS verdict, and the change merged. −10.9% is an improvement, not a fix; the two
items in "Out of scope" are where the remaining weight is.
