# VT-35: Parallel lanes share one database, one dev server and one scratch directory (benchmark finding E13)
- status: In Review
- labels: parallel, gate, field-finding
- estimate: 0.5d
- type: Bug

**30-second summary:** in the benchmark arm's ZK-2 round the DEV lane and three reviewers ran at
once on ONE SQLite file, ONE dev server and ONE scratch directory. Fixture-restoring hooks raced;
the reviewers reported 3, 2 and 14 failures that did not reproduce, one reviewer's eslint reddened
on another's scratch file, and a fabricated CONFIRMED was one tired reviewer away (~20 minutes of
triage). Since VT-31 `init` pins a checkout-unique port, but parallel lanes run in worktrees that
SHARE `vteam.config.yaml`, so they still shared `app.url`, and nothing derived a per-worktree
database. Now a lane derives its environment from the worktree it runs in, `app_check` honours it,
and `parallel_check` reds two in-flight worktrees that have not done so or that share a port or a
database.

## Why
docs/BENCHMARK.md "How the two runs went" and ~/Documents/vteam-vs-bmad/arm-a-vteam/RUNLOG.md row E13
(owner's machine). Parallel mode (VT-5..VT-7) made fan-out possible; isolation was still prose
("prefer an isolated copy of dev.db"). Spec: core/doctrine/parallel-transport.md rule 4. no UI.

## Acceptance criteria
- Given two worktrees of one repo / When `lane_env.sh` runs in each / Then they export different `PORT`, `APP_URL` and (sqlite) `DATABASE_URL`, the same worktree derives the same values twice, and a `--lane R1` in one worktree differs from its `main` lane.
- Given a plain checkout / When `lane_env.sh` runs / Then its `PORT` equals the port `vteam init` wrote into `app.url` (one scheme, two writers).
- Given `APP_URL` exported / When `app_check.sh` runs / Then it probes that URL before the config's `app.url`.
- Given `team.parallel > 1` and two in-flight branches checked out in worktrees / When `parallel_check` runs / Then it is RED until both worktrees carry a lane environment, and RED again when two lane environments claim one port or one database; a single in-flight worktree is exempt.
- Given the doctrine / When read / Then team.md rule 4 and parallel-transport.md rule 4 name the helper and the rule "one worktree, one port, one database, one scratch dir; reviewers never run against the author's environment".

## Out of scope
Non-sqlite datasources (the helper prints a hint, it does not create databases); migrating/seeding the lane database (the lane runs the profile's commands against `DATABASE_URL`); Orca's `worker-start` sourcing the helper automatically (the worker prompt says to).
