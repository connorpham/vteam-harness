# VT-24: Fix the 13 defects the 2026-09-17 line-by-line code review found
- status: In Review

- labels: framework, code-review, gates
- estimate: 1d
- type: Bug

**30-second summary:** A full read of the framework's 64 files (18,602 lines) found three gates that
were declared but never wired, four installer gaps, and six smaller defects. This ticket fixes every
one, each with a selftest or e2e case that proves the red.

## Why
The field trial taught the lesson "a gate the workflow names but no manifest runs is prose" (VT-17,
VT-21). The same class of hole exists inside the framework itself: `stale_verdict_check` is named by 5
workflows and run by 0 profiles; `preflight.sh` runs the ENTIRE gate on every `/dev T0`; a provider
switched after init is unreachable. Spec: docs/team/ops.md §gates, docs/DESIGN.md §2 (config), spec §
review of 2026-09-17 (evd/VT-24/dev/review-findings.md).

## Acceptance criteria
- Given `preflight.sh` runs / When it checks the gate driver / Then `gate.py --help` exits 0 without running one step, and an unknown `--flag` is refused
- Given any of the 6 profiles / When `gate.sh` runs on a markdown-tracker repo / Then `stale_verdict_check.py` runs as a step (declared skip on remote trackers)
- Given `tracker.provider` or `design.provider` changed after init / When `vteam update` runs / Then the provider file is installed under `.vteam/providers/`
- Given the copilot or windsurf adapter / When a workflow description contains `: ` / Then the rendered frontmatter is valid YAML (quoted)
- Given a packaged agent or session-start hook changed upstream / When `vteam update` runs on an unmodified copy / Then it is refreshed through the manifest guard (a user-edited copy is parked as `.new`)
- Given a framework file removed upstream / When `vteam update` runs / Then an unmodified copy is pruned and reported; a modified copy is kept and reported; an `owned` path is never touched
- Given a repo with `prisma/` but no `next` dependency / When `vteam init` detects the profile / Then it picks `node`, and the nextjs-prisma `typegen` step declares a skip when `next` is absent
- Given `bdd_report_check.py --root <dir>` / When no reports exist / Then it exits 0 instead of crashing
- Given `x: [a,,b]` or a first line indented deeper than a later one / When either config parser reads it / Then both die with the same message
- Given `--attach` re-runs / When manifest.md has prose after `## TRACKER ATTACHMENTS` / Then only that section is replaced
- Given a decision row whose Question cell carries a date / When `schedule_check` reads deadlines / Then the Due column decides
- Given `paths.evidence` is not `evd` / When graph_check / log_check / route_check run / Then the configured path is used

## Out of scope
Untested tools (`orca_team.sh`, `ui-evidence.mjs`, `ui_fidelity.mjs`, `auth.mjs`, `prepublish-check.mjs`) get
no new tests here — filed as VT-25. No workflow prose changes. no UI.
