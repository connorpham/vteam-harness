# VT-11: nextjs-prisma profile and init must work on a pnpm/turbo monorepo (app not at the repo root)

- status: To Do
- assignee: Connor Pham
- estimate: 1d
- labels: profiles, init, monorepo, no UI

## Why

Field trial 2026-09-08/09 on a pnpm + Turborepo monorepo shaped like a real
client codebase (apps/tenant = Next 15.3.6, packages/database = Prisma 6.8.2).
Every assumption of the `nextjs-prisma` profile broke on first contact and had
to be hand-patched in the project's `.vteam/profiles/nextjs-prisma/gates.yaml`
(kept as a locally-modified manifest, `.new` parked by every `update`):

1. `init` detects `nextjs-prisma` only when `prisma/schema.prisma` sits at the
   repo root → a monorepo silently gets the `node` profile unless `--profile`.
2. `prisma-generate` requires `prisma/schema.prisma` at root; the schema lives
   in `packages/database/prisma/schema.prisma`.
3. `typegen: npx next typegen` — runs at the root (no `app/`), and the command
   does not exist below Next 15.5 (15.3.6 treats "typegen" as a directory arg).
4. `types: npx tsc --noEmit` at the root — no root tsconfig in a workspace.
5. `token-check` reads `<git root>/.next/static/chunks`; the build lands in
   `apps/tenant/.next`.
6. `e2e: npm run test:e2e` hard-codes npm although `{package_manager}` exists.
7. `app.start` / `app.url` are single-valued — parallel worktree workers each need
   their own port (the trial used `TENANT_PORT` + `TENANT_URL` env overrides).
8. No Prisma-aware `db-check.sh` template; `psql` rejects Prisma's `?schema=`
   query string.
9. Next < 15.5 writes `next dev` and `next build` into the same `.next` → a gate
   build while the dev server runs corrupts it (the trial used `NEXT_DIST_DIR`).

## Acceptance criteria (testable)

1. **Given** a repo whose only `schema.prisma` is under `packages/*/prisma/` and
   whose Next app is under `apps/*`, **When** `init` runs without `--profile`,
   **Then** it picks `nextjs-prisma` and writes the app/schema paths it found into
   `stack:` (e.g. `stack.app_dir`, `stack.prisma_schema`); a root-layout repo
   keeps today's values.
2. **Given** that config, **When** `gate.sh` runs, **Then** `prisma-generate`,
   `typegen`, `types`, `build`, `token-check` and `e2e` execute inside the
   detected app/package via `{package_manager}` and the detected dirs — none
   uses a hard-coded root path or `npm`; `token-check` reads
   `<app_dir>/.next/static/chunks`.
3. **Given** Next < 15.5, **When** the `typegen` step runs, **Then** it is a
   declared skip naming the version (`requires_cmd` probe), not a red.
4. **Given** `team.parallel > 1`, **When** a DEV worker is briefed, **Then**
   `app.start`/`app.url` support a per-worker port (documented env or template
   variable) and `app_check.sh --url` is the proof — doctrine says which.
5. `init` writes a `.vteam/db-check.sh` for the `nextjs-prisma` profile that
   strips Prisma's query string before `psql` (or uses Prisma to ping).
6. Selftests/e2e: a monorepo fixture in `tests/e2e.mjs` proves 1–3; README
   counts updated by the numbers the guard prints; `gate.sh` GREEN, `doctor`
   green.

## Out of scope

- The dev/build `.next` collision (project-side `distDir`; document it in the
