# VT-39: the ledger's cost column is the last piece of testimony in a framework that demands evidence
- status: In Review
- labels: ledger, cost, honesty
- estimate: 0.5d
- type: Task

**30-second summary:** every ledger row ends `done · tok ≈ <N>k`, typed by the agent from memory.
`lib/ledger.py` parses it and nothing ever checked it. Meanwhile `usage --sync` already publishes
MEASURED session-log numbers into `{paths.pm}/usage/<actor>.md`. The new advisory gate step `cost`
compares them PER DAY, and its louder finding is staleness: in this repo the measured record
stopped on 2026-08-24 while the ledger ran to 2026-09-18 — 25 days in which every cost number
quietly went back to self-reported, and nothing said so.

## Why
The framework's whole argument is "evidence, not claims", and its own cost column was a claim. The
comparison is only possible per day — a session log knows the day and the model, never which ticket
a token belonged to — so the check produces no per-ticket number and says why. It is advisory by
construction: an estimate and a measurement differ, and a gate that reds on that teaches people to
inflate the estimate until it stops reding. Spec: `core/scripts/lib/ledger.py` (row grammar),
`core/scripts/perf_report.py:parse_usage_dir` (usage grammar), `core/workflows/pm.md` step 6. no UI.

## Acceptance criteria
- Given a day with both ledger rows and a measured row / When `cost_check` runs / Then it compares the summed `tok ≈` against measured new spend (input + cache-write + output) and warns only past `ledger.cost_tolerance_factor`, naming the date, both numbers and the ratio.
- Given ledger rows more than `ledger.usage_max_stale_days` newer than the newest measured row / When it runs / Then it says the measured record stopped and names both dates.
- Given a repo with no usage directory / When it runs / Then it prints one line and exits 0 — no wall of findings for the repos that never sync.
- Given days with ledger rows and no measured row / When it runs / Then they are one compact line, not one line per day.
- Given the gate / When it runs anywhere / Then `cost` is advisory: a finding is reported and never blocks a commit.
- Given `core/workflows/pm.md` / When read / Then it states that a divergence is a finding about the estimate and that a ledger row is never edited to match the measurement.

## Out of scope
Per-ticket cost attribution (not derivable from a session log — the check says so rather than faking it); changing what `usage --sync` writes; pricing or money figures; making the step blocking.
