# VT-32: Review rounds and BA challenger rounds have no ceiling
- status: In Review
- labels: cost, review, ba, gate
- estimate: 0.5d
- type: Task

**30-second summary:** the 2026-09-03 benchmark arm spent three review rounds (~2.5 h) on one
ticket and three challenger rounds sharding a frozen, AC-coded spec (2 h 05 min before a backlog
existed); it cut itself to one fix round per ticket mid-run and finished. Nothing in the framework
said when to stop. Now two config knobs do, and `review_check.py` counts the rounds instead of
trusting prose.

## Why
Speed was the benchmark's real finding (4 h 29 min to the first feature commit vs 1 h 44 min;
docs/BENCHMARK.md "How the two runs went"). The arm's own mid-run decision
(`arm-a-vteam/RUNLOG.md`, "Mid-run decision on review cost") is the design: reviewer count from
config, one fix round unless the finding is a security defect, briefs as prioritised attack lists.
Spec: core/workflows/dev.md T4b, core/workflows/ba.md B3. no UI.

## Acceptance criteria
- Given a new `vteam init` / When the config is generated / Then it carries `review.max_rounds: 1` and `ba.challenger_rounds: 1`, and docs/GUIDE.md's documented block and the example config carry the same keys (tests/conformance.mjs still green).
- Given a dossier with `## Round 2` and `review.max_rounds: 1` / When `review_check.py <KEY>` runs / Then it is RED naming the count and the knob; a `SECURITY`-tagged finding or a high-stakes diff makes the same dossier green; an absent knob is green with "no ceiling" printed.
- Given `{paths.specs}/reviews/<feature>-backlog.md` with `## Round 2` and `ba.challenger_rounds: 1` / When `review_check.py --ba <feature>` runs / Then RED; a `SPEC`-tagged finding lifts it.
- Given core/workflows/dev.md and ba.md / When read / Then each says when the ceiling applies, what the agent does when it is hit (answered, not fixed), what lifts it, and that a brief is a prioritised attack list; the rendered skills carry the same text.
- Given the selftest / When `round_gaps` is neutered or the SECURITY lift removed / Then `review_check.py --selftest` is RED (code-only mutations, test kept).

## Out of scope
Enabling the ceiling in this repository's own `vteam.config.yaml` (VT-25's dossier records a legitimate second round for a CI-red on Linux and would go red retroactively — the owner's call, see the tasksheet); machine-detecting "every source row already carries a code" (the E4 verbatim_gate regex gap belongs to the setup-tax ticket); reviewer count defaults.
