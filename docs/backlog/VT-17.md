# VT-17: put the QA lane's own evidence gate into the gate

- status: In Review
- assignee: Connor Pham
- estimate: 0.25d
- labels: gates, qa, evidence, from-field-trial

## Why

`core/workflows/qa.md` names `evd_check.py` **twelve times** — at V4, V5, V7 and in the closing
checklist, with "must be green before V5" stated outright. `gate.sh` never ran it. A check that
only executes when someone remembers to type it is not a gate, and the field trial produced the
exact failure it exists to prevent: TB-8's first verification pack shipped a `REPORT.md` claiming
**ten test cases** with **zero** case folders, no `manifest.md` and one debate card. `gate.sh` was
GREEN throughout. It took a challenger agent, spawned by the same lane that wrote the pack, to run
`evd_check` by hand and find it.

Two smaller faults came with it, both found by sweeping the existing packs: vteam's own **VT-1** is
`Done` with a `REPORT.md` and no `verifysheet.md`, and nothing had ever noticed.

## What it does

`evd_check.py --sweep` checks every pack that carries a `REPORT.md`, without being told which
ticket. Three design choices, each because of a way the naive version would be wrong:

- **The expected case count comes from the report itself** — the distinct `TC_<n>` it cites — so a
  report cannot claim more cases than the folder holds. That is precisely the TB-8 failure, and no
  human has to remember an `--expect-tcs` number.
- **Only CLOSED tickets fail.** A pack for a ticket still in review may legitimately be half
  written; failing it would make the gate unusable mid-verification. Open packs are reported.
- **Packs with no `KIND:` anywhere are reported, not failed**, which is the same v1/v2 line
  `check_tree` already draws internally. Retro-fitting a test plan onto a verification nobody can
  re-run would be fabricating evidence — worse than an old pack being incomplete. VT-1 lands here.

## Acceptance criteria (testable)

1. **Given** a repo with evidence packs, **When** `evd_check.py --sweep` runs, **Then** it reports
   one line per pack with the ticket's status, and exits 1 only if a **closed, non-legacy** pack
   fails.
2. **Given** the existing `--evd <dir>` invocation, **When** it runs, **Then** it behaves exactly
   as before, and `--selftest` stays green (9 + 14 mutations).
3. **Given** the six stack profiles, **When** `gate.sh` runs, **Then an `evd` step executes**
   between `ledger` and the rest, and skips with a declared reason on a repo with no `evd/`.
4. **Given** a pack that a report cites a case for and the folder does not hold, **When** the gate
   runs, **Then** it goes **RED at evd** — demonstrated by deleting a real case folder, not argued.
5. **Given** a legacy pack on a closed ticket (VT-1), **When** the sweep runs, **Then** it is
   reported with the reason and the gate stays green.

## Out of scope

- Writing a `verifysheet.md` for VT-1 after the fact. The sweep reports it; inventing the plan that
  was never written would be the opposite of what this ticket is for.
- `--expect-tcs` in sweep mode. The report's own citations replace it by design.
